# Этап 11 — сценарное тестирование

Этап выполнен по подтверждению пользователя. Настоящие внешние подключения
не проверялись: действующих ключей в проекте нет, реальных данных и отправок нет.
Этап 12 (Render) не выполнялся.

## Результат

- 163 теста pytest прошли. Добавлены 10 проверок границ Assistant: устаревшие и
  некорректно типизированные события, отсутствие/смена согласия, отказ чтения БД,
  неудачная инициализация, попытка подтверждения без серверного черновика.
- Все 12 сценариев исходного задания прошли с настоящим временным PostgreSQL.
  HTTP-запросы Supabase RPC выполнялись через прежний тестовый мост к SQL.
  Использовались настоящий адаптер LLM и Telegram-клиент, но ответы внешних
  HTTP API были подменены. Это не проверка облачной Supabase, OpenAI или Telegram.
- `pip check` не обнаружил конфликтов зависимостей.
- Тестовый PostgreSQL остановлен, временная БД и её пароль удалены.
  Существующие базы не изменялись.
- Изменения рабочей логики не потребовались: найденных отказов новых сценариев нет.

Машиночитаемый результат фактического прогона: `STAGE_11_RESULTS.json`.
`status=passed` записывается только после успешных проверок и удаления временной БД.
Файл `STAGE_11_CODE.md` содержит полный код файлов этапа для просмотра.

## Повторить в Windows PowerShell

```powershell
Set-Location 'C:\Users\user\Desktop\дима разработка\03-AI Assistant urist\legal_ai_consultant'
$env:PYTHONIOENCODING = 'utf-8'
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -u tests/check_schema_local.py --report
Get-Content STAGE_11_RESULTS.json -Encoding UTF8
```

Для последней проверки требуются `initdb`, `pg_ctl`, `psql` в PATH. На этом
компьютере установлен PostgreSQL 17.6. Runner создаёт отдельный кластер в TEMP,
случайный пароль и свободный локальный порт; после завершения останавливает и
удаляет только этот кластер. Рабочие ключи и `.env` не требуются.

Если SQL-проверка завершается ошибкой, она возвращает ненулевой код; отчёт
не будет отмечен успешным. Не принимайте старый снимок исходников или ранее
созданный отчёт за доказательство нового успешного запуска.

## Что остаётся проверить

- Реальную доступность выбранной модели, Supabase/PostgREST и Telegram.
- Поведение на реальном телефоне. Встроенный браузер не применил запрошенную
  ширину 390 px и оставил 1086 px: мобильная проверка не подтверждена.
- Нагрузку и ограничения выбранного хостинга. Приложение пока рассчитано на
  один процесс; многопроцессное масштабирование не подтверждено.
- Полноту защиты от инъекций и юридическую достоверность: прохождение примеров
  не является доказательством защиты от всех атак или правильности любого ответа.

Для настоящих подключений владелец заполняет `.env` локально: ключ и модель LLM,
URL и серверный ключ Supabase с применённой схемой, токен бота и ID Telegram-чата.
Ключи в чат не отправляются. Для публичной обработки нужны реквизиты оператора,
утверждённая политика/согласия и проверка фактического размещения и передачи данных.

Сейчас от владельца ничего не требуется для выполнения локальных тестов.
Следующий этап — подготовка развёртывания на Render после подтверждения.
