# Этап 10 — Gradio и сборка диалога

Реализован русскоязычный веб-чат и серверный Assistant. Следующий этап 11
не начат: ниже приведены проверки, необходимые для сборки этапа 10.

## Что реализовано

- `python app.py` запускает Gradio 6.30.0 на `0.0.0.0`, порт берётся из `PORT`
  (по умолчанию 7860). Публичный туннель отключён, аналитика Gradio отключена.
- Приветствие, переписка, поле ввода, отправка по кнопке/Enter, индикатор обработки,
  безопасные сообщения об ошибках, восстановление и очистка истории.
- Router определяет стоимость, запись и общий вопрос. Цены берутся из базы знаний;
  общий вопрос отправляется через прежний адаптер модели. Judge проверяет ответ
  до сохранения и показа. Шаблоны сервера проверяются локально; при `JUDGE_MODE=llm`
  дополнительный запрос применяется только к ответам на общий вопрос и делит
  бюджет с основным адаптером. Ошибка модели не вызывает автоматический повтор.
- Запись: запрос записи → тема/описание → имя → телефон → просмотр данных →
  отдельный флажок и кнопка подтверждения. Обычное «да» не даёт согласия.
  Вопрос о цене или общий вопрос может прервать запись, сохранив её этап.
- Реальные функции prepare/consent/create_lead вызываются сервером. Модель
  не выбирает сессию и не подтверждает согласие. Повторы используют прежний
  request_id; успех строится только из результата БД.
- Заявка и задача уведомления создаются вместе. Telegram обслуживается прежним
  отдельным worker, поэтому отключение Telegram не теряет заявку.
- Memory v2 сохраняет этап, имя, телефон, описание и ключ черновика в БД.
  Состояния v1 читаются и обновляются автоматически; новая SQL-миграция не нужна.
  Требуются прежние schema.sql и миграции 002–004.
- Отдельные кнопки удаления истории и заявок с подтверждением; история очищает
  черновик и согласие. Заявки можно удалить также после очистки истории.
  Уже доставленное уведомление Telegram эта операция не удаляет.

## Доступ к истории и ограничения

В браузере BrowserState хранит только UUID и случайный секрет владения сессией,
не содержимое переписки. Сами сообщения и черновик загружаются из БД. При
обновлении страницы и перезапуске сервера доступ сохраняется в том же браузере
и на том же origin (протокол/адрес/порт). Другой браузер получает другую сессию.
UUID без 256-битного секрета не даёт доступа; в БД хранится его хеш.

Шифрование BrowserState выполняется фронтендом; его ключ не является серверным
секретом и не служит авторизацией. LocalStorage не защищает от XSS/доступа к
профилю браузера. Не используйте общее устройство. API-ключи туда не передаются.
Кнопка нового диалога забывает доступ в браузере, но не удаляет данные БД;
сначала используйте удаление истории и заявок. Утрата хранилища браузера означает
утрату доступа к прежнему диалогу.

Приложение рассчитано на один процесс/экземпляр. Очередь ограничена 32 событиями,
обработчики сериализованы, сервер использует блокировки и версии БД для защиты
от устаревших вкладок. Полная межпроцессная блокировка хода и общий постоянный
API-бюджет для нескольких экземпляров не реализованы. Масштабировать пока нельзя.
Лимит API сохраняет прежние ограничения: по умолчанию 5 запросов/минуту,
20 за жизнь процесса. Ограничения длины применяются сервером, история показа —
40 сообщений; LLM получает до 6 кратких предыдущих реплик общего диалога,
включая проверенные уточняющие вопросы ассистента, без этапов сбора контактов.

Контактные этапы и история записи не передаются модели. Общие вопросы проходят
удаление известных имени/телефона, шаблонов контактов и секретов. Это не полная
автоматическая анонимизация произвольного текста: вводить реальные данные нельзя.
При ошибке БД история не заменяется вымышленной успешной операцией; восстановите
диалог кнопкой, затем повторяйте подтверждение прежнего черновика.

## Локальный запуск — PowerShell

```powershell
Set-Location 'C:\Users\user\Desktop\дима разработка\03-AI Assistant urist\legal_ai_consultant'
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# Если .env ещё отсутствует, создайте копию один раз (не перезаписывайте заполненный):
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:7860. Без корректных LLM/Supabase настроек и применённой
схемы окно открывается, но диалог выключен. Рабочие ключи указываются только
локально в `.env`; не присылайте их в чат. Выберите реальную модель в `LLM_MODEL`.

Для очереди уведомлений в другом окне PowerShell, из того же каталога:

```powershell
.\.venv\Scripts\python.exe app.py --check-telegram
.\.venv\Scripts\python.exe app.py --notification-worker
```

Обработчик действительно отправляет уведомления в настроенный Telegram-чат.
Не запускайте его с чужими или рабочими данными без разрешения.

## Как проверить сборку

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe tests/check_schema_local.py
```

Последняя команда требует установленных initdb/pg_ctl/psql в PATH. Она создаёт
и удаляет отдельный временный PostgreSQL, не затрагивает существующие базы.
SQL выполняется через тестовый HTTP-мост: это не проверка облачного PostgREST.
Внешние LLM и Telegram в тестах подменены и обозначены как тестовые.

Необязательный стенд для проверки кнопок в браузере:

```powershell
.\.venv\Scripts\python.exe -u tests/check_schema_local.py --ui
```

После проверок открывается http://127.0.0.1:7861. В состоянии явно написано:
временная PostgreSQL, LLM подменена, Telegram не отправляется. Ctrl+C останавливает
стенд и удаляет тестовую БД. Это тестовый помощник, не режим настоящего приложения.

Проверьте: согласие → «Как взыскать алименты?» → стоимость → «Хочу записаться» →
описание → «Тест» → «+70000000000» → «да» (заявки ещё нет) → отдельное согласие →
подтверждение. Повтор не создаёт дубль. Обновление страницы возвращает историю.
Проверьте отказ «не согласен», очистку, отдельное удаление заявок и новый диалог.

## Что требуется от владельца

Для проверки настоящих интеграций: ключ и модель LLM, URL и серверный ключ
выделенной Supabase с применённой схемой, бот/чат Telegram для worker.
`PRIVACY_POLICY_URL` — HTTPS-ссылка на утверждённую политику оператора.
Пока её нет, интерфейс сообщает об отсутствии ссылки; фиктивная политика не создана.

До публичного сбора реальных данных нужны реквизиты оператора, утверждённые тексты
политики/согласий и проверка фактического размещения/передачи данных. Этап 10
не подтверждает выполнение этих требований и не является публичным запуском.
Развёртывание Render относится к этапу 12 после разрешения.

## Результаты проверки этапа

- 153 теста pytest прошли; `pip check` не обнаружил конфликтов; исходники компилируются.
- Полный цикл Assistant проверен с настоящим временным PostgreSQL через тестовый
  HTTP-мост, с подменой LLM и Telegram. Доступность облачных сервисов не подтверждена.
- В браузере проверены начало диалога, последовательный сбор данных, явное
  подтверждение заявки и восстановление истории после обновления страницы.
- Итоговый интерфейс без ключей открывается на 7860, действия с интеграциями
  выключены; встроенная кнопка очистки только экрана скрыта.
- Проверка мобильной ширины через встроенный браузер не подтверждена:
  инструмент изменения viewport оставил фактическую ширину 1086 px. Использованы
  стандартные адаптивные компоненты Gradio; отдельно проверьте телефон перед запуском.
- Временная БД тестового стенда остановлена и удалена; рабочие базы не затрагивались.
