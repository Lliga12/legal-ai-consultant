# Этап 4: Router

## Назначение

`core/router.py` определяет PRICE, BOOKING, GENERAL, OTHER по локальным правилам
русского языка. Подключение к облаку, ключи и дополнительные зависимости не нужны
сверх уже установленного requirements.txt. Вызов LLM для классификации не используется:
Router не отправляет сообщения и контакты внешнему провайдеру и не расходует API-квоту.

Результат — неизменяемый `RouteResult`: основное намерение, дополнительные намерения,
предполагаемая тема, причина выбора, уточняющий вопрос для неоднозначного ввода,
признаки отмены записи и отказа от согласия. `legal_topic` — метка классификации,
не подтверждение, что юрист оказывает конкретную услугу. Возможность помощи
проверяется по базе знаний в будущем цикле Assistant.

Суммы, ответы по праву, извлечение контактов, валидация телефона и регистрация
заявки в обязанности Router не входят. Согласие Router не предоставляет и не фиксирует.

## Правила и контекст

- Явный вопрос о стоимости получает PRICE; одновременное желание записаться
  сохраняется в `secondary_intents`, чтобы Assistant мог обработать оба запроса.
- Вопрос по правовой теме получает GENERAL. Неясный или посторонний ввод получает
  OTHER и уточнение. Одиночное слово BOOKING не является командой управления.
- Сервис передаёт историю как список `Message`. Анализируются последние 12 сообщений
  из переданных максимум 100. Тема извлекается только из сообщений клиента.
- Для короткого «А сколько?» используется предыдущая юридическая тема.
  «Подробнее» продолжает распознанный общий вопрос или вопрос о стоимости.
- При записи предпочтителен явный `BookingStage`, полученный с сервера.
  Строка в сообщении клиента не меняет этап. До реализации Memory этот этап
  можно передать вручную из Python для проверки.
- Без состояния продолжение записи восстанавливается осторожно: в недавней истории
  должны быть запрос клиента на запись и последний уточняющий вопрос ассистента.
  Одного имени, телефона или «да» для начала записи недостаточно.
- Вопрос о цене или новый юридический вопрос может прервать сбор данных.
  Caller обязан сохранить/обновить состояние диалога; Router историю не изменяет.
- Отказ от согласия и отмена возвращаются отдельными признаками. Будущий Assistant
  должен остановить оформление. Router сам ничего не сохраняет и не удаляет.

Локальные правила не обеспечивают универсального понимания языка: опечатки,
сложные отрицания, цитаты и необычные перефразировки могут классифицироваться
неверно. Обнаружение нескольких типовых попыток изменения инструкций — лишь
дополнительная проверка, а не полная защита от prompt injection.
Серверные проверки согласия, разрешений и аргументов инструментов обязательны
независимо от результата маршрутизации.

Router не хранит состояние между вызовами. Изоляция зависит от того, что вызывающая
сторона передаёт историю только нужной сессии; авторизация сессий будет реализована
на этапах Supabase и Memory. Ограничения количества сообщений защищают размер
обрабатываемой истории, а не заменяют ограничения частоты запросов.

## Проверка в Windows PowerShell

```powershell
Set-Location 'C:\Users\user\Desktop\дима разработка\03-AI Assistant urist\legal_ai_consultant'
.\.venv\Scripts\python.exe .\app.py --check-router
.\.venv\Scripts\python.exe .\app.py --route 'Сколько стоит развод? Хочу записаться'
.\.venv\Scripts\python.exe -m pytest .\tests\test_router.py -q
.\.venv\Scripts\python.exe -m pytest -q
```

`--check-router` демонстрирует шесть запросов: PRICE, BOOKING, GENERAL, OTHER,
PRICE с темой из истории и продолжение BOOKING с ответом на вопрос об имени.
`--route` классифицирует одну фразу без истории. Ключи и `.env` не требуются.
Не передавайте реальные контакты в аргументах команд: они сохраняются в истории shell.

## Использование в Python

```python
from core.router import BookingStage, Router
from llm.base import Message

router = Router()
history = [
    Message('user', 'Хочу записаться по вопросу алиментов'),
    Message('assistant', 'Как вас зовут?'),
]
result = router.route('Анна', history, booking_stage=BookingStage.NAME)
print(result.intent.value)  # BOOKING
print(result.legal_topic)   # Взыскание алиментов
```

## Границы этапа

Проверено в `.venv` на Python 3.10.1: 27 тестов Router и 12 тестов адаптеров LLM,
итого `39 passed`. Демонстрация `--check-router` завершилась с кодом 0.
Проверка `--route 'Сколько стоит развод? Хочу записаться'` вернула PRICE,
дополнительное BOOKING и тему «Развод».

Сохраняемой истории пока нет. Реальные заявки, Telegram, Judge и веб-чат
не подключались. Доступность LLM не подтверждена: для Router она не требуется.
Переход к этапу 5 — только после подтверждения пользователя.
