# Этап 3: облачная модель

## Что реализовано

`config.py` загружает `.env` рядом с приложением через python-dotenv. Переменные
окружения сервера имеют приоритет. Ключи исключены из repr конфигурации и
пользовательских ошибок; тела ошибок провайдера не печатаются.

`llm/base.py` задаёт общий интерфейс `generate(system, messages) → LLMResponse`.
`llm/factory.py` выбирает Gemini, OpenAI или совместимый Chat Completions API.
Смена провайдера не требует изменений вызывающего кода.
HTTP-клиент закрывается через контекстный менеджер. Запросы синхронные;
асинхронное выполнение и очередь интерфейса будут настроены на этапе Gradio.

Gemini использует generateContent, OpenAI — Chat Completions. Системная инструкция
передаётся отдельно от сообщений клиента. Модель с неподдерживаемым форматом API
может отклонить запрос: произвольная модель не обязательно совместима с адаптером.
Функции инструментов на этом этапе модели не доступны.

Документация, по которой подготовлены запросы:

- [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
- [Gemini generateContent](https://ai.google.dev/api/generate-content)

Текст базы знаний пока не передаётся модели. Команда проверки отправляет только
фиксированный технический запрос без персональных данных. Консультационный цикл,
Router и Judge будут добавлены на соответствующих этапах.

## Установка в Windows PowerShell

```powershell
Set-Location 'C:\Users\user\Desktop\дима разработка\03-AI Assistant urist\legal_ai_consultant'
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
if (-not (Test-Path -LiteralPath '.\.env')) {
    Copy-Item -LiteralPath '.\.env.example' -Destination '.\.env'
}
notepad .\.env
```

Активация окружения не нужна. Команда копирования не перезаписывает существующий
`.env`. Ключ внесите локально в этот файл; не отправляйте его в чат или GitHub.

Для Gemini установите `LLM_PROVIDER=gemini`, `GEMINI_API_KEY` и `LLM_MODEL`.
Имя модели возьмите из своего кабинета провайдера, вместо `your_model_name`.

Для OpenAI установите `LLM_PROVIDER=openai`, `OPENAI_API_KEY`, `LLM_MODEL` и
оставьте `OPENAI_BASE_URL=https://api.openai.com/v1`.

Для другого сервиса установите `LLM_PROVIDER=openai_compatible`, отдельный
`OPENAI_COMPATIBLE_API_KEY`, его HTTPS `OPENAI_BASE_URL` (до `/chat/completions`)
и `LLM_MODEL`. При необходимости выберите `OPENAI_TOKEN_PARAMETER=max_tokens`.
Ключ этого сервиса не берётся автоматически из `OPENAI_API_KEY`.
Совместимость стороннего сервиса нужно проверить реальным запросом.

## Проверка

```powershell
# Без сети и ключей:
.\.venv\Scripts\python.exe .\app.py
.\.venv\Scripts\python.exe -m pytest -q

# Один реальный запрос; может тарифицироваться провайдером:
.\.venv\Scripts\python.exe .\app.py --check-llm
```

Успешный реальный запрос выводит `LLM API ответил`, провайдера, модель и текст.
Без ключа/модели команда завершится до обращения к API. Ошибка HTTP, тайм-аут,
блокировка, отсутствие текста и усечение ответа не считаются успехом.
Проверки с MockTransport проверяют запросы и обработку ответов, а не доступность API.

## Ограничения запросов и расходов

- По умолчанию: 5 попыток в минуту и 20 попыток за жизнь одного объекта адаптера.
  Экземпляр нужно создавать один раз на процесс и переиспользовать.
- Один запрос: максимум 16000 символов входа (включая системную инструкцию и историю)
  и 512 выходных токенов, если модель поддерживает выбранный параметр.
- Тайм-аут HTTP-операций: 30 секунд, включая ожидание ответа. Это тайм-аут операций
  транспорта, а не абсолютный срок всего выполнения.
- Автоматические повторы и переходы по HTTP-редиректам отключены.
  Неуспешная попытка расходует локальный бюджет: провайдер мог уже обработать запрос.
- Лимиты потокобезопасны, но локальны: новый процесс или новый экземпляр адаптера
  начинает новый бюджет. CLI создаёт новый адаптер при каждом запуске.
- Денежный бюджет не вычисляется: цены и доступность моделей не предполагаются.
  Для ограничения фактических расходов настройте квоты/бюджет в кабинете провайдера.
  До публичного запуска нужны общие постоянные лимиты на сервере через БД.

Суммарное ограничение символов не является точным счётчиком входных токенов.
Разделение ролей не гарантирует защиты от prompt injection. Фильтрация данных,
серверные разрешения инструментов и Judge будут реализованы позднее.
