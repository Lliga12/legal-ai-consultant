# GitHub → Render: первый тестовый запуск

Подготовлены render.yaml и вход по паролю. Облачный деплой подтверждается только
после создания сервиса владельцем и проверки его адреса/логов. Пока допускаются
только вымышленные данные; настоящие LLM, Supabase и Telegram не проверены.

## Что сделать в Render

Существующий Barber-AI оставляем. В проекте My project можно разместить несколько
сервисов; новый проект создавать не нужно.

1. New → Web Service → подключить GitHub и выбрать `Lliga12/legal-ai-consultant`.
2. Настройки: Branch `main`, Runtime `Python 3`, Root Directory **пусто**.
3. Build Command: `python -m pip install -r requirements.txt`.
4. Start Command: `python app.py`.
5. Instance Type: **Free**, один экземпляр. Автоматический деплой выключить.
6. В Environment добавить `WEB_AUTH_USERNAME` (новый тестовый логин) и
   `WEB_AUTH_PASSWORD` (новый пароль длиной 16–200 символов).
   Это пароль тестового сайта, не пароль GitHub/Render. Не присылать его в чат.
7. Создать сервис, дождаться успешной сборки и открыть его HTTPS-адрес.
   Войти с тестовым логином. Без ключей откроется интерфейс с выключенным диалогом.

Вариант с готовыми настройками: New → Blueprint → тот же репозиторий,
путь `render.yaml`. Проверить, что создаётся только один бесплатный Web Service,
и ввести запрошенные тестовые логин/пароль. Платный worker в этот Blueprint не включён.

`.python-version` выбирает Python 3.11 с последним доступным patch. Локальные
проверки выполнены на Python 3.10; Linux/Python 3.11 проверяется сборкой Render.
Сервер слушает 0.0.0.0 и PORT, который выдаёт Render. Без тестовых логина/пароля
на Render сервер не запускается. Health check `/` проверяет страницу входа,
а не доступность облачных интеграций. Секреты не передаются через GitHub.

## После первого запуска

В Environment этого сервиса добавить:

| Переменная | Значение |
| --- | --- |
| LLM_PROVIDER | gemini (или openai/openai_compatible) |
| LLM_MODEL | точный код доступной вашему аккаунту модели |
| GEMINI_API_KEY | ключ Gemini при выборе gemini |
| OPENAI_API_KEY | ключ при выборе openai |
| OPENAI_COMPATIBLE_API_KEY и OPENAI_BASE_URL | при выборе совместимого API |
| SUPABASE_URL | адрес выделенного тестового проекта |
| SUPABASE_KEY | серверный Secret key; не publishable/anon |
| JUDGE_MODE | local для первого запуска |
| PRIVACY_POLICY_URL | утверждённая политика оператора, когда подготовлена |

В пустом выделенном проекте Supabase применить по очереди `database/schema.sql`,
`database/migrations/002_memory.sql`, `003_lead_tools.sql`, `004_telegram.sql`.
Не применять первоначальную схему к рабочей базе другого проекта.
После обновления Environment выполнить повторный Deploy и проверить вымышленный
диалог, заявку, повтор подтверждения, восстановление и удаление.
Лимит ответа LLM по умолчанию 512 токенов может быть мал для модели с рассуждением;
совместимость конкретной модели и доступность её оплаты проверяются отдельно.

## Telegram

Веб-сервис сохраняет задачи уведомлений в Supabase. Для постоянной отправки нужен
отдельный Background Worker, тариф которого согласуется до создания.
Команды: Build `python -m pip install -r requirements.txt`, Start
`python app.py --notification-worker`. Один экземпляр.
Environment worker: SUPABASE_URL, SUPABASE_KEY, TELEGRAM_BOT_TOKEN,
TELEGRAM_CHAT_ID, TELEGRAM_INCLUDE_CONTACT=false. WEB_AUTH ему не нужен.
Перед включением проверить получателя и накопившуюся тестовую очередь:
запуск обработчика действительно отправляет сообщения.

## Бесплатный тариф и существующий Barber-AI

750 часов Free общие для Workspace. Спящий сервис часы не расходует; после
15 минут без входящего трафика бесплатный Web Service засыпает. При исчерпании
часов бесплатные сервисы останавливаются до следующего месяца. Отдельно
учитываются сборки и исходящий трафик. Это тестовый тариф, не обещание
постоянной доступности. [Ограничения Render](https://render.com/docs/free).

Данные остаются в Supabase после перезапуска. Память процесса Gradio и лимит
API сбрасываются при перезапуске/сне. Не включать несколько экземпляров:
межпроцессная блокировка полного диалога пока не реализована.
BrowserState хранит доступ к сессии только в прежнем браузере и origin;
его шифрование не заменяет защиту от XSS и доступа к профилю браузера.

## Предварительная оценка обработки данных

Пароль и согласие не подтверждают выполнение требований локализации и
трансграничной передачи. Для первичного сбора данных граждан РФ необходимо
отдельно оценить требования части 5 статьи 18 №152-ФЗ; для зарубежной передачи —
процедуры статьи 12, включая уведомление и сведения о получателях.
[Действующая редакция закона](https://www.consultant.ru/document/cons_doc_LAW_61801/),
[статья 12](https://www.consultant.ru/document/cons_doc_LAW_61801/e4ebbe1780de623c7cf32a59ca82a7bb523a25dd/).

Управляемая Supabase размещает проекты в выбранных AWS-регионах; размещение
логов и служебных данных также требует оценки. [Регионы](https://supabase.com/docs/guides/platform/regions),
[размещение и передача](https://supabase.com/legal/privacy-resources/data-residency-and-transfers-faq).
Текущая зарубежная схема не подтверждена для реальных клиентов. До их подключения
нужно определить страны баз/логов/резервных копий и получателей, согласовать
архитектуру локализации, реквизиты оператора, политику и тексты согласий.
Это предварительная оценка проекта; тестировать только вымышленные обращения.

## Проверки подготовки

174 pytest-теста прошли; pip check не обнаружил конфликтов. HTTP-проверка Gradio
подтвердила вход, отказ анонимному запросу конфигурации, отсутствие пароля в
клиентской конфигурации и запрет выдачи SQL-файлов. YAML проверен по официальной
JSON Schema Render. Это не подтверждение уже выполненного облачного деплоя.

```powershell
Set-Location 'C:\Users\user\Desktop\дима разработка\03-AI Assistant urist\legal_ai_consultant'
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe tests/check_web_local.py
```

Мобильное отображение и работа на Render проверяются после запуска отдельно.

[Python](https://render.com/docs/python-version),
